# 2026-08-16 – Lazy grid alpha

`compose_core` now includes a generic `LazyGrid` and an independently exported
`lazyGridLayout()` calculation. This is partial parity with Compose's adaptive
`LazyVerticalGrid`, intentionally scoped to deterministic fixed-height rows.

## Contract

- `minimumItemWidth` determines a responsive column count from the measured
  container width. Remaining horizontal space is divided evenly.
- `itemHeight` is required and numeric. It is the fixed height used for total
  extent, absolute item placement, and viewport windowing.
- `columnSpacing`, `rowSpacing`, and `overscanRows` are optional non-negative
  numeric values.
- On native Valdi clients, `LazyGrid` observes its parent scroll viewport. It
  does not create a nested scrolling surface.
- Native clients normally materialize only the end-exclusive
  `[firstIndex, endIndex)` window. Set `viewportWindowing={false}` to retain the
  complete collection in the accessibility tree.
- Pinned Valdi Web uses an `IntersectionObserver` callback that does not provide
  continuous local scroll offsets for tall elements. Web therefore
  materializes the complete collection as a correctness-first fallback.
- `keyForItem` supplies stable identity when callers have it; indices are the
  deterministic fallback.
- Caller styling is applied to an outer wrapper. The inner measured canvas
  remains unpadded so layout styles cannot invalidate its geometry.

The pure `lazyGridLayout()` helper returns column count, item width, row stride,
total content height, and the bounded item window. The separately exported
`lazyGridMaterializationWindow()` chooses between that native window and full
materialization. Tests cover responsive geometry, exact row boundaries, a
partial final row, an empty grid, bounded deep scrolling, the explicit full
mode, and the Web fallback.

## Current limitations

- Variable-height or measured-height items are unsupported because they would
  make the unseen vertical extent unknowable without a separate size index.
- Column spans, sticky headers, reverse layout, and horizontal grids are not
  implemented.
- Native window updates depend on Valdi delivering `onViewportChanged` from an
  ancestor scroll view. Before the first viewport measurement, the first row
  plus the configured overscan is composed as a deterministic bootstrap window.
- Pinned native Valdi exposes no virtual collection/count or accessibility
  scroll bridge. A windowed grid cannot expose off-window children to sequential
  VoiceOver/TalkBack traversal; use `viewportWindowing={false}` when complete
  accessibility traversal takes priority over bounded materialization.
- Web is correct but not windowed until Valdi Web exposes continuous element-
  local viewport offsets.
- This alpha does not expose scroll position control or programmatic scrolling.

The compose playground includes a bounded 24-item example for visual inspection.

## Validation targets

The deterministic helper specs execute in Valdi Standalone through
`//valdi_modules/compose_core:test`. The structural shell smoke test remains at
`//valdi_modules/compose_core:compose_core_placeholder_test`, and the bounded
example compiles through `//apps/compose_playground:app_macos`.
